토큰은 어디에 쓰나

중요: tokens.css 같은 별도 파일은 쓰지 않는다.

Tailwind CDN이 외부 CSS 파일의 @theme을 못 읽기 때문이다.
색·간격 같은 값은 각 페이지 index.html 안 <style type="text/tailwindcss">의 @theme { } 블록에 그대로 둔다.

<style type="text/tailwindcss">
  @theme {
    --color-brand: #7bcc12;
    --color-brand-ink: #052e00;
  }
</style>

다른 곳에서는 var(--color-brand)처럼 참조한다. 새 raw 값을 직접 쓰지 않는다.

자동 차단(hook)은 뭘 막나

.claude/hooks/check-hardcode.fixed.mjs가 파일을 고치기 직전에 자동으로 검사한다.
.html / .css / .js 파일만 검사한다.

막는 것예시
하드코딩 색색상 코드·rgb·rgba 직접 입력
arbitrary Tailwind대괄호로 값을 직접 넣는 클래스
허용 안 된 CDN화이트리스트 7개 URL 외 <script src>·<link href>

예외: @theme { } 블록 안 색상은 안 막는다(토큰 정의니까).
줄 끝에 exempt 주석을 붙이면 그 줄만 빠진다(자세한 문법은 원본 md 참고).

위반이 있으면 편집 자체가 막힌다(exit 2). 고쳐야 다음으로 넘어간다.

스킬 4개 — 언제 쓰나

상황스킬실제 작업하는 에이전트
Figma 시안을 코드로 옮길 때/figma-to-codefigma-implementer
Figma 없이 새 섹션(hero 등) 만들 때/new-sectionsection-builder
흩어진 하드코딩을 토큰으로 정리할 때/sync-tokenstoken-guardian
작업 끝나고 규칙 지켰는지 확인할 때/review-designdesign-reviewer

에이전트 4개 — 각자 하는 일

  1. figma-implementer — Figma 노드를 읽어 코드로 옮긴다. Clarify → Reuse → Implement → Evaluate 4단계를 직접 수행한다.
  2. token-guardian — 하드코딩을 찾아 @theme에 토큰으로 추가한다. index.html의 @theme 블록만 고친다. 다른 곳은 읽기만 한다.
  3. section-builder — Figma 없이 기존 토큰만으로 섹션을 만든다. 요청한 섹션 외 파일은 안 건드린다.
  4. design-reviewer — 코드를 안 고친다. 5가지(하드코딩·토큰·CDN·접근성·화면대조)를 검사해 PASS/FAIL만 낸다.

정해진 순서: Clarify → Reuse → Implement → Evaluate

새 화면·섹션을 만들 때는 항상 이 순서를 따른다.

  1. Clarify — 뭘 만드는지, 애매한 부분은 없는지 먼저 확인한다.
  2. Reuse — 새로 짜기 전에 기존 토큰·구조를 먼저 찾아 쓴다.
  3. Implement — 요청한 범위만 최소로 고친다.
  4. Evaluate — 다 고친 뒤 직접 다시 열어 하드코딩이 남았는지 확인한다.

여러 페이지의 공통 영역 정리 (extract-common.js)

.claude/hooks/extract-common.js는 자동 훅이 아니라 수동 도구다.
/new-section 실행 시 1단계에서 자동으로 불린다(페이지가 여러 개일 때만).

직접 실행하려면:

node .claude/hooks/extract-common.js

common/head.html, common/header.html, common/footer.html을 만들고, 페이지 간 불일치를 알려준다.

실전 예시

시나리오 1 — Figma 시안 하나를 새 섹션으로 넣기

/figma-to-code
→ Figma URL과 넣을 파일 위치를 물어봄
→ figma-implementer가 4단계로 작업
→ 끝나면 /review-design으로 확인

시나리오 2 — 옛날 코드에 하드코딩이 많이 남아있을 때

/sync-tokens
→ 프로젝트 전체 또는 특정 파일 범위를 물어봄
→ token-guardian이 찾은 값을 @theme에 등록
→ 코드 파일에 남은 자리는 목록으로 보고만 함(직접 안 고침)
→ 그 목록 보고 figma-implementer나 section-builder에게 실제 교체를 맡김
