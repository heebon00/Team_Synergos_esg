README 자동 작성 프롬프트 (저장소 로그 분석형)
저장소 안의 실제 기록(커밋 메시지, 프롬프트 로그, 코드)을 근거로 README를 자동 작성하게 하는 프롬프트입니다. AGY(또는 Claude Code 등 저장소에 접근 가능한 AI 에이전트)에 그대로 붙여넣습니다. 손으로 채울 빈칸이 없습니다 — 에이전트가 저장소에서 직접 찾아 씁니다.

이 저장소를 분석해서 최상위에 README.md를 새로 만들어 줘. 내용을 지어내지 말고, 아래 순서로 저장소 안의 실제 기록에서 뽑아 써.
1단계 — 증거 수집 (작성 전에 반드시 수행) 다음을 순서대로 확인하고, 각각에서 찾은 사실을 먼저 목록으로 나열해:
git log --oneline --all — 전체 커밋 메시지. 작업 순서와 날짜별 진행 내역을 파악해
저장소 안의 프롬프트 기록 파일 — prompts/, docs/, .md 파일 등에서 AI에게 보냈던 프롬프트와 작업 로그를 찾아. 파일명에 "프롬프트", "prompt", "log", "회의록"이 들어간 파일을 우선 확인해
실제 코드 — index.html, 설정 파일(package.json 등), 폴더 구조에서 기술 스택과 페이지 구성을 확인해
배포 설정 — GitHub Pages 설정 또는 배포 관련 파일·브랜치에서 배포 URL을 확인해
2단계 — README 작성 1단계에서 확인된 사실만으로 아래 구성으로 작성해:
프로젝트 소개 — ESG 소개 사이트 리디자인 프로젝트. 대상 기업명과 팀명은 코드·문서에서 찾은 실제 값을 써
페이지 구성 — 실제 존재하는 HTML/라우트 기준으로 페이지 목록과 역할 (홈 / ESG 소개 / 보고서 모음 / 문의)
기술 스택 — 설정 파일과 코드에서 확인된 것만
개발 방식 — AI에게 프롬프트로 요청해 코드를 생성하고 검증하는 방식(바이브 코딩)으로 제작했음을 밝히고, 프롬프트 기록에서 찾은 실제 작업 흐름을 날짜순으로 3~6줄 요약해 (예: "홈 페이지 시안 → 프롬프트로 코드 생성 → 모바일 깨짐 수정"). 대표 프롬프트 1~2개를 짧게 인용해도 좋아
실행·확인 방법 — 배포 URL, 로컬 확인 방법이 있으면 함께
팀원 — 커밋 작성자와 문서에서 확인된 이름
비고 — 교육 목적 프로젝트 한 줄
문체 규칙 — 자연스럽고 쉬운 한국어
처음 보는 사람도 읽히도록 쉬운 한국어로 써. 번역투("~에 의해 생성됨", "~를 제공합니다")를 쓰지 마
문장은 짧게, 한 문장에 한 가지 내용만. 종결은 합니다체(~합니다, ~입니다)로 통일해
전문용어는 처음 나올 때 괄호로 풀어 써 (예: "배포(만든 사이트를 인터넷에 올려 누구나 접속하게 하는 일)")
영어 단어를 그대로 쓰지 말고 한국어로 풀어 써. 고유명사(GitHub, Figma, Tailwind 등)만 예외
작성 규칙 — 확인 안 되는 항목 처리
저장소에서 확인 안 되는 항목이 있으면 추측하지 말고, 작성을 시작하기 전에 부족한 항목을 한 번에 모아 나에게 질문해. 내가 답하면 그 값으로 채워
내가 "자동으로 진행해"라고 답하면 질문 없이 완성하되, 빈 항목은 [확인 필요]로 표시해
개발 방식 요약의 각 줄 끝에 근거를 괄호로 붙여 (커밋 해시 앞 7자리 또는 파일 경로)
마크다운 헤더와 리스트만 사용, 배지·이모지 장식 금지, 전체 60줄 이내
작성 후, README에 쓴 내용과 근거(어느 파일·커밋에서 왔는지) 대응표를 채팅으로 별도 출력해 — 검수용

사용 시 주의
프롬프트 기록이 저장소가 아니라 노션에만 있는 팀은, 노션의 프롬프트 로그를 docs/prompt-log.md로 저장소에 먼저 옮긴 뒤 실행하면 질문 없이 진행됩니다. 옮기지 않으면 에이전트가 개발 방식 내용을 질문으로 요구합니다.
커밋 메시지가 "update" 같은 무의미한 문구뿐이면 작업 흐름 복원이 부정확해집니다. 결과의 근거 표기를 반드시 검수하십시오.
